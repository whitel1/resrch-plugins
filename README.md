# resrch-plugins

Official plugin content for [Resrch](https://github.com/whitel1/resrch-app) —
language packs, themes, and runtime reference plugins — plus the registry
catalog that powers in-app plugin discovery and the review pipeline for
community submissions.

Plugin **contracts** (manifest schema, guest API, error envelopes, registry
index schema) live in the [`resrch`](https://github.com/whitel1/resrch)
repository; this repository is **content only**. It validates and packages
that content with `rdev plugin check` / `rdev plugin package`.

## Layout

```
plugins/
  app.resrch.markdown-toolkit/     # runtime reference plugin (command/transform/analyzer/panel)
  app.resrch.theme-pack/           # Nord, Rosé Pine, Warm Paper UI themes
  app.resrch.accessibility-pack/   # colorblind-safe & low-stimulus editor packs
  app.resrch.language-pack-fr/     # French product language pack (partial)
registry/
  index.json                # GENERATED by scripts/build_registry.py — do not edit
scripts/                    # check / package / catalog build entry points
docs/authoring.md           # how to write and submit a plugin
```

Every directory under `plugins/` is one plugin, named after its manifest id.
Community submissions land in the same tree through review; the registry
builder records the maintainer set per entry.

## Plugin kinds

| Kind | What it contributes | Example |
| --- | --- | --- |
| Resource | themes, theme packs, locales, product language packs, settings | `app.resrch.theme-pack` |
| Runtime (shell) | commands, transforms, analyzers, script-rendered panels | `app.resrch.markdown-toolkit` |
| Hybrid | both of the above | — |

## Validate and package

```bash
# full contract + locale validation (needs the resrch-app checkout beside this one)
scripts/check-all.sh

# build every .rplugin and regenerate registry/index.json
scripts/build-registry.py
```

`.rplugin` packages are immutable per `(id, version)`: publishing re-runs the
check, pins the SHA-256 and byte size into `registry/index.json` (schema:
`plugin-registry-index-v1`), and attaches the package to a GitHub release.

## Submitting a community plugin

Open a PR adding `plugins/community/<your-plugin-id>/`. CI must pass
`rdev plugin check` and a maintainer review of the requested permissions and
declared resources. See `docs/authoring.md` for the manifest rules, the
`Plugin.*` localization namespace, and the packaging checklist.
