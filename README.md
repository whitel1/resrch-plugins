# resrch-plugins

Official plugin content for [Resrch](https://github.com/whitel1/resrch-app) —
language packs, themes, and runtime reference plugins — plus the registry
catalog that powers in-app plugin discovery and the review pipeline for
community submissions.

Plugin **contracts** (manifest schema, guest API, error envelopes, registry
index schema) live in the [`resrch`](https://github.com/whitel1/resrch)
repository; this repository is **content only**. It validates and packages
that content with `rdev plugin check` / `rdev plugin package`.

## Layout

```
plugins/
  app.resrch.markdown-toolkit/     # runtime reference plugin (command/transform/analyzer/panel)
  app.resrch.status-kit/           # status bar reference plugin (declarative item + SDK-driven panel)
  app.resrch.benchmark-samples/    # benchmark provider reference (contributes rows to the pending review queue)
  app.resrch.theme-pack/           # Nord, Rosé Pine, Warm Paper UI themes
  app.resrch.accessibility-pack/   # colorblind-safe & low-stimulus editor packs
  app.resrch.language-pack-fr/     # French product language pack (partial)
  app.resrch.language-pack-zh-hant # Traditional Chinese pack (complete; zh-CN fallback chain)
registry/
  index.json                # GENERATED by rdev plugin index — do not edit
dist/                       # committed .rplugin packages the index pins
scripts/                    # check / package / catalog build entry points
docs/authoring.md           # how to write and submit a plugin
docs/resrch-plugin.d.ts     # IntelliSense reference for the session shim surface
```

Every directory directly under `plugins/` is one published plugin, named
after its manifest id; community submissions are staged under
`plugins/community/` (validated by CI, not yet published) and promoted to
the top level after review. The registry builder (`rdev plugin index`, owned
by the `rdev` toolchain and typed by the `plugin-registry-index-v1`
contract) records the maintainer set per entry.

## Plugin kinds

| Kind | What it contributes | Example |
| --- | --- | --- |
| Resource | themes, theme packs, locales, product language packs, settings | `app.resrch.theme-pack` |
| Runtime (shell) | commands, transforms, analyzers, panels, status bar items | `app.resrch.status-kit` |
| Runtime (shell) | `[[benchmark_providers]]` contributions (rows land in the pending review queue) | `app.resrch.benchmark-samples` |
| Hybrid | both of the above | `app.resrch.markdown-toolkit` |

## Validate and package

```bash
# full contract + locale validation (needs the resrch-app checkout beside this one)
scripts/check-all.sh

# check + package every plugin and merge registry/index.json (same gates, one command)
rdev plugin index --manifest ../resrch-app/i18n.toml

# validate the committed catalog with the registry contract: pins match dist/, no orphans
rdev plugin index --verify
```

`.rplugin` packages are immutable per `(id, version)` and committed under
`dist/`. The catalog build is append-only: published versions are preserved,
a new version must be strictly newer than the latest, and changing content
(including `min_app_version`) under a pinned version fails the build — bump
the version instead. A push to `main` deploys the index and packages to
GitHub Pages, the default source the in-app marketplace fetches
(`https://whitel1.github.io/resrch-plugins/registry/index.json`).

## Submitting a community plugin

Open a PR adding `plugins/community/<your-plugin-id>/`. CI must pass
`rdev plugin check` (community plugins are validated exactly like official
ones) and a maintainer review of the requested permissions and declared
resources; on acceptance a maintainer promotes the plugin to the top level
of `plugins/`, which is what publishes it to the catalog. See
`docs/authoring.md` for the manifest rules, the `Plugin.*` localization
namespace, and the packaging checklist.

## Documentation

User-facing documentation lives on the website: the
[plugin registry and distribution](https://resrch.ai/en/docs/development/plugin-registry/)
page summarizes this repository's catalog rules, signing, and publishing
pipeline (Chinese: [插件注册表与分发](https://resrch.ai/zh-cn/docs/development/plugin-registry/)),
and the [official plugin catalog](https://resrch.ai/en/docs/reference/plugin-catalog/)
listing is regenerated from the committed `registry/index.json` whenever
the docs site rebuilds. This README and `docs/authoring.md` remain the
repository-side working documents.
